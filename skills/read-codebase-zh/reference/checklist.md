# 质量清单：read-codebase-zh

回复用户之前逐条核对。每一条都是以前的报告踩过的坑。

## 内容
- [ ] 有**要求 / 目标 / 限制**表，并且后面每一章都明显在回答其中某一行。
- [ ] 每个主要组件章节都回答了：职责 · 难点 · 原理 · 契约 · 连接 · 容易误解的地方。
- [ ] 有一节**端到端生命周期**：一个具体请求穿过所有组件，标出每一步在哪个仓库、哪一步不公开。
- [ ] 不显然的默认值和行为是从代码里读出来的（配置默认值、中间件顺序、懒加载），不是猜的。
- [ ] 推断出来而非读到的内容，在正文里标明了。
- [ ] 历史类说法（许可证变更、改名、删除）用 GitHub API 或旧 SHA 的文件核实过。
- [ ] 在影响定制的地方写明了“仓库里没有什么”（闭源后端、SaaS、生成代码）。
- [ ] 许可证章节（读者可能 fork、分发或部署时）：每部分的许可证和证据、场景表、例外（素材、图标、商标、CLA）、历史、“不是法律意见”。
- [ ] 贡献章节：真实存在的环境命令、项目的 review 规则、适合入手的方向、定制路线。
- [ ] 没有空话，没有逐文件罗列目录树；中文平实，没有翻译腔。

## 图
- [ ] 中等项目 8–16 张图；每张都有图注，说明该看什么，并带源码链接。
- [ ] `--strict` 构建通过（没有重叠、溢出、标签放不下、链接错误）。
- [ ] **`.shots/` 里每张截图都打开看过**：没有连线穿过节点、没有标签压在节点上、挪动节点能消掉的交叉都消掉了、箭头方向正确。
- [ ] 随时间展开的过程用了带高亮的 `::: steps`。

## 链接与类比
- [ ] 60–150 个固定源码链接；具体说法旁边都有链接。
- [ ] `--links` 通过（所有外链返回 200）。
- [ ] 2–4 个类比，每个都写明映射关系，并紧挨着它解释的机制。

## 输出
- [ ] `report.html` 和 `report.pdf` 都在输出目录里（不在被分析的仓库里）。
- [ ] PDF 页数合理，抽查过几页（图能正常显示，表格没被截断）。
- [ ] 已发布到 `adhoc-lean-grills`（或说明了跳过原因）：只提交四个报告文件和 README 一行，没有本机路径、邮箱或密钥，线上地址返回 200。
- [ ] 最终回复：线上地址、本地路径、各章一句话总结、固定的 SHA、做过的验证、未能核实的地方。除 `adhoc-lean-grills` 外，用户没要求就不 commit / push。
